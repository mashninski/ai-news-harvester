# CLAUDE.md — ai-news-harvester

Контекст для Claude Code и любого нового чата, который откроет этот репозиторий.

## Что это

Сборщик новостей об ИИ для будущего раздела `mashninski.com/naviny`. Три шага:

- **коллектор** (`collect.py`, этап 3 плана) — скачивает 9 источников, приводит
  записи к общему виду, отбрасывает уже виденное, склеивает одну новость из
  разных источников;
- **пайплайн** (`pipeline.py`, этап 4) — triage на Haiku 4.5, генерация на
  Sonnet 5, линтер антикалек, fix-проход. Всё через Batch API. На выходе
  черновики карточек `output/cards/<hash>.json`. Карточки — **наркамаўкай**
  (с 02.10.2026); конвертер в тарашкевіцу с guard-маркерами включается
  переменной `AI_NEWS_ORTHOGRAPHY=tarask` — раздел «Орфография» ниже;
- **публикация** (`publish.py`, этап 5) — черновики → один PR в `mashninski-site`,
  по файлу `content/naviny/<hash>.json` на карточку. Мерж PR = публикация.

Запускает всё это воркфлоу `.github/workflows/harvest.yml` раз в 2 часа: основной
путь — Worker `strymy-bot` в Cloudflare, запасной — `schedule` GitHub (раздел
«Устройство запуска» ниже). Фронт (этап 6) живёт в сайте.

Полная спека и план — в **приватном репозитории сайта** `mashninski-site`
(локально `D:\production\mashninski-site`): `claude/ai-news-spec.md` — как устроено
(§2 — источники, §5 — архитектура), `claude/ai-news-plan.md` — этапы и стоимость.
Хронология решений — `claude/journal.md` там же.

Своего журнала у этого репозитория нет и заводить его не надо: продуктовые решения
живут в журнале сайта, здесь — только устройство кода.

## Раскладка

```
collect.py              коллектор
pipeline.py             пайплайн: triage → генерация → конвертер → линтер → fix → черновик
llm.py                  клиент Anthropic (ключ из AI_NEWS_ANTHROPIC_KEY), модели
prompts.py              промпты triage, генерации, fix; сборка system prompt
tarask.py               конвертер: guard-маркеры, вызов Node, поиск подозрительных замен.
                        Работает только при AI_NEWS_ORTHOGRAPHY=tarask; не удалять
lint.py                 линтер антикалек, разбивка на предложения
tools/taraskevize/      Node-подпроект: npm-пакет taraskevizer и convert.mjs
schema.sql              схема файла состояния, выполняется при каждом запуске
data/state.sqlite       состояние коллектора и пайплайна. Не в git: в Actions живёт в кэше
output/cards/           черновики карточек, в .gitignore — их везёт publish.py
publish.py              публикация: PR с карточками в репозиторий сайта через GitHub API
eval_corpus.py          прогон на эталонном корпусе сайта (критерий этапа 2)
data/eval/              его входы, карточки и отчёт; в .gitignore
api_check.py            один вызов API — проверка ключа (критерий этапа 0)
probe_feeds.py          ручная проверка фидов-кандидатов перед добавлением
.github/workflows/harvest.yml   запуск по расписанию: коллектор → пайплайн → публикация
tests/                  pytest; сеть и API не нужны. Тесты конвертера и режима tarask — нужен node
requirements.txt
```

## Запуск

```bash
pip install -r requirements.txt
(cd tools/taraskevize && npm ci)   # конвертер — только для tarask и его тестов; нужен Node 20+
python collect.py              # печатает новые материалы, записывает их в состояние
python collect.py --dry-run    # то же, но состояние не трогает
python collect.py --json out.json   # плюс новые материалы в JSON
python pipeline.py             # забрать готовые батчи, отправить triage
python pipeline.py --generate --fix   # то же плюс батчи генерации и fix (fix — не чаще раза в сутки)
python pipeline.py --wait --generate --fix   # ходить по кругу, пока все батчи не вернутся
python pipeline.py --status    # что где лежит, сколько ждёт генерации по дням, потрачено, остаток бюджета
python publish.py --preview DIR   # без сети: файлы, тело PR и комментарии — в DIR
python publish.py              # PR в main со всеми ещё не предложенными карточками
python publish.py --base naviny-test   # PR в тестовую ветку — прод не трогается
python -m pytest               # тесты
```

Коллектору ключей не нужно. Пайплайну нужны:

- `AI_NEWS_ANTHROPIC_KEY` — переменная окружения с ключом Anthropic API.
  **Не `ANTHROPIC_API_KEY`:** это имя в облачных сессиях Claude Code занято
  самой платформой, и SDK молча взял бы не тот ключ. Ключ передаётся в клиент
  явно (`llm.make_client`). Запрет — про переменную процесса, не про имя
  секрета в Actions: там секрет называется `ANTHROPIC_API_KEY`, и воркфлоу
  кладёт его в `AI_NEWS_ANTHROPIC_KEY`;
- `AI_NEWS_ORTHOGRAPHY` — `narkamauka` (по умолчанию) или `tarask`, раздел
  «Орфография» ниже;
- `AI_NEWS_MONTHLY_BUDGET_USD` — месячный бюджет в $, по умолчанию 28
  («Предохранители бюджета» ниже);
- репозиторий сайта рядом — `../mashninski-site` или путь в `AI_NEWS_SITE_REPO`.
  Оттуда читаются стайлгайд, глоссарий, антикальки, написания имён
  (`ai-news-names.json`) и guard-словарь. Сюда они не
  копируются: сайт приватный, этот репозиторий публичный.

Публикации (`publish.py`) нужен `AI_NEWS_SITE_TOKEN` — fine-grained токен GitHub
только на `mashninski-site`, права Contents и Pull requests — read and write.
Локально — переменная окружения или строка в `.env.local` рядом с `publish.py`
(в `.gitignore`), в Actions — GitHub Secret. Anthropic API публикация не вызывает.

## Устройство, если правишь код

- **Все источники в списке `SOURCES`.** Тип `rss` — через feedparser (Atom он тоже
  читает), тип `sitemap` — свой адаптер. Новый источник — одна строка.
- **Каждый источник в своём try/except** (`collect()`): сеть, таймаут, HTTP-ошибка,
  битый XML роняют только его, в лог идёт `ПРОПУЩЕН источник …`, в отчёте — строка
  «Источники с ошибкой». Покрыто тестом `test_broken_sources_are_skipped_not_fatal`.
  Уровнем ниже — то же для записи: кривая ссылка или дата одной записи фида
  (адреса в sitemap) пропускает только её, а не весь источник
  (`test_bad_entry_skips_only_itself`). Упали **все** источники — выход с кодом 1:
  это уже сеть или сам коллектор, а не битый фид, и воркфлоу должен покраснеть.
  Один упавший источник — штатно, VentureBeat падает каждый прогон.
- **feedparser не считает ошибкой HTML-страницу и пустой ответ** — отдаёт ноль записей
  без флага ошибки. Поэтому ответ без распознанной версии фида и без записей считается
  ошибкой источника, иначе умерший фид молчал бы. Обрезанный XML, из которого
  feedparser спас часть записей, берётся с предупреждением.
- **Идентичность записи — нормализованный URL** (`url_key`): без `utm_*`, `ref`,
  `fbclid` и подобных меток, без `#якоря`, схемы, `www.` и завершающего слэша,
  параметры отсортированы. `hash` — sha1 от него. В поле `url` лежит `clean_url` —
  рабочая ссылка без меток, по `url_key` ходить нельзя. Новая метка в ссылках
  источника — добавить в `TRACKING_PARAMS`, иначе виденное начнёт возвращаться.
- **Окно свежести `MAX_AGE_DAYS`.** Фиды OpenAI и Hugging Face отдают весь архив
  (сотни записей). Всё старше окна пишется в состояние со статусом `stale`
  и дальше не идёт. Без этого первый прогон выдал бы ~2500 «новых».
- **Anthropic — по sitemap.** Новое — это URL `/news/<slug>`, которого нет в
  состоянии; `lastmod` меняется и при правке старой статьи, поэтому новизну не
  определяет. `lastmod` служит только дешёвым фильтром: страницу с `lastmod`
  старше окна не качаем. Страница качается один раз, только для нового URL;
  не скачалась — URL не пишется в состояние и будет в следующем прогоне.
  Не больше `PAGE_FETCH_LIMIT` страниц за прогон.
- **Дата у Anthropic** — `article:published_time`, если есть; иначе дата текстом
  «Sep 23, 2026» со страницы (в разметке Anthropic есть только она); иначе `lastmod`.
- **Склейка заголовков** (`cluster`, `same_story`): разные источники, публикации
  не дальше `CLUSTER_WINDOW_HOURS`, не меньше `CLUSTER_MIN_SHARED` общих значимых
  слов и не меньше `CLUSTER_MIN_OVERLAP` от более короткого заголовка. Значимые —
  без стоп-слов (`STOPWORDS`: служебные английские и общие для новостей об ИИ
  вроде «launches», «model») и **без слов серии**: слово, которое у источника стоит
  в двух заголовках за окно, — название линейки («gemini», «3.8»), а не признак
  новости. Порог подобран на живых данных, разбор — в журнале сайта, 24.09.2026.
  Меняешь — прогони тесты склейки: там живые пары из этой выборки.
- **Склейка идёт и с прошлыми прогонами.** Пост вендора и статья портала о нём
  обычно приходят в разные прогоны. Новое сравнивается с отданным за окно
  (`load_known`); совпавшее пишется в состояние как `duplicate` с `primary_hash`
  основного и печатается отдельным списком «повторы отданных раньше».
- **Основной в кластере** — уже отданный, иначе пост вендора (`VENDORS`), иначе
  более ранний. Сравнение только с основным, не со всеми участниками кластера —
  иначе цепочка A≈B≈C склеила бы разные A и C.
- **Под браузер не маскируемся.** `USER_AGENT` честный. VentureBeat режет ботов
  (429 всем, кроме браузеров и известных читалок вроде Feedly) — сейчас он штатно
  пропускается каждый прогон. Что с ним делать — решение автора, см. журнал сайта.
- **TechCrunch — только повтором** (`SECONDARY_ONLY`, рашэнне аўтара
  08.10.2026, журнал сайта). В фиде у него лишь анонс в одно предложение
  (`description`, 60–320 знаков), и карточки из него выходили пустыми.
  Страницу не качаем: `robots.txt` TechCrunch поимённо запрещает ИИ-ботов,
  в том числе `anthropic-ai`. При склейке такой источник всегда последний —
  основным становится любой другой; без пары он пишется повтором без
  основного (`status = 'duplicate'`, `primary_hash` NULL) — в генерацию
  не идёт и якорем склейки не становится, так что пост компании, пришедший
  позже, получает свою карточку. Пайплайн снимает в `rejected` и то, что
  было отобрано до правила. Тесты — `tests/test_secondary_only.py`;
  тесты склейки в `test_collect.py` правило выключают (живые пары с TechCrunch).
- **Ars Technica AI — портал, как TechCrunch** (добавлен 03.10.2026, этап 8в,
  решение автора — журнал сайта, «Ars Technica и Mistral — берём оба»).
  robots.txt боту отвечает 403, в браузере — поимённый запрет ИИ-ботов,
  включая Anthropic, но для `*` фид открыт и наш User-Agent не назван.
  Прецедент: текстовый запрет, не адресованный нашему боту, источник
  не останавливает; техническую защиту (403/429/капча на сам фид) не обходим —
  закроют фид, источник штатно уйдёт в «Источники с ошибкой». В фиде —
  начало статьи, 640–1500 знаков, докачка не нужна. Каждая запись кончается
  абзацами-ссылками «Read full article» и «Comments» — `html_to_text` их
  выкидывает (`FEED_LINK_LINES`, только абзац целиком).
- **Mistral AI — вендор с докачкой страницы** (добавлен 03.10.2026, этап 8в,
  та же запись журнала сайта): в `SOURCES`, `VENDORS` и
  `pipeline.PAGE_FETCH_SOURCES`. В записи фида только анонс в одно
  предложение (100–160 знаков, меньше `MIN_BODY_ANY`) — текст берётся
  со страницы, ниже «Докачка страницы». Фид отдаёт архив с 2023 года
  (88 записей), старое отсекает окно свежести. robots.txt разрешает всё.
- **Остальные кандидаты из спеки сайта (§2) проверены 03.10.2026** (комментарий
  в `SOURCES`, журнал сайта того же числа): Microsoft AI и Meta AI фидов
  не отдают. Новый кандидат —
  сначала `probe_feeds.py`: он печатает и ответ robots.txt; «не прочитан»
  (код 4xx) — не «разрешено», файл смотреть руками.
- **Текст статей в состоянии — только временно**: body нового материала
  и его повторов из того же прогона ждёт в таблице `article`, пока пайплайн
  не сделает карточку, не отсеет материал, не отложит его в `too_old` или
  `failed`, — потом стирается вместе с текстами повторов (`forget_body`).
  Постоянно хранится только нужное для дедупа.

## Орфография: наркамаўка по умолчанию, тарашкевіца — переменной

Тарашкевіца выключена решением автора 02.10.2026 (журнал сайта, «Этап 8а»
в `ai-news-plan.md`): конвертер `taraskevizer` ошибается, свой ещё не написан
(`ideas.md` сайта). Переключатель — `AI_NEWS_ORTHOGRAPHY`, в Actions —
переменная репозитория с тем же именем (не задана — `narkamauka`).

- **`narkamauka`** — на сайт идёт текст модели как есть. Шаг конвертера —
  тождество (`Resources.convert`), Node не вызывается и в Actions не ставится.
  Guard-маркеры и `suspicious_changes` не работают — заметок «канвертар» нет.
  Имена в промпте — только форма `write`, без «(на сайце: …)». Fix-проход
  ставит исправленное предложение на место без второй конвертации. Линтер
  ищет фразу словаря только так, как она записана, — наркамаўкай; что словарь
  так и ловит, проверяет `test_linter_catches_dictionary_forms_as_written`.
- **`tarask`** — прежнее поведение байт в байт: конвертер с guard-маркерами,
  заметки о подозрительных заменах, имена с формой `be`, промпт со словами
  «тарашкевіцу зробіць канвертар». Включается одной переменной, когда будет
  свой конвертер; `tarask.py`, `tools/taraskevize` и guard-словарь сайта
  для этого и остаются.
- **В обоих режимах** глоссарий записан тарашкевіцай, а модель пишет то же
  слово наркамаўкай — это правило в справочном блоке остаётся. Поля
  карточки называются по-старому: `tk` в состоянии и тексты карточки —
  «то, что идёт на сайт», `narkamauka` — что написала модель (при
  наркамаўке совпадают). В черновике — поле `orthography`.
- **`eval_corpus.py` всегда в режиме `tarask`**: корпус и судья —
  тарашкевіцай. Его не запускать без «да» автора (≈ $3).

## Устройство пайплайна, если правишь код

- **Батчи переживают перезапуск.** Каждый запуск `pipeline.py` сначала забирает
  готовые батчи из таблицы `batch` (отправленные прошлыми запусками), потом
  отправляет новые на всё, что ждёт своего шага в таблице `item`. Шаги:
  `new → triage_sent → triaged → generate_sent → linted → fix_sent → draft`,
  плюс `rejected`, `too_old`, `failed`. Неудачный результат возвращает материал
  на шаг назад, после `MAX_ATTEMPTS` — `failed` с причиной в `error`. Уже
  разобранный результат повторно не разбирается: берутся только материалы, которые
  всё ещё ждут именно этот батч. Схема — `schema.sql`, раздел «Пайплайн».
- **Текст статьи лежит в таблице `article`** — коллектор кладёт туда body новых
  основных материалов и их повторов из того же прогона (первые 700 слов, только
  из фида — страниц ради повторов не качаем). Когда карточка готова, материал
  отсеян, устарел или кончились попытки, текст стирается вместе с текстами
  повторов: в состоянии остаётся только нужное для дедупа.
- **Второй источник в генерации** (этап 8б, журнал сайта, 03.10.2026: у GPT-6.1
  Sol цифры TechCrunch не попали в пересказ — повтор уходил одним заголовком).
  `prompts.generate_user` отдаёт текст первого по порядку повтора, у которого
  он есть, — не больше `SOURCE2_MAX_WORDS` (600) слов, блоком `<source2>`
  с названием источника и заголовком; остальные повторы — заголовками, как
  раньше. У позднего повтора (пришёл, когда основной уже отдан) текста нет:
  основной мог уже уйти в генерацию, тогда — только заголовок. В задаче
  генерации строка «факты бяры з усіх крыніц; калі крыніцы разыходзяцца —
  так і пішы». Оценка: ≈ +1000 токенов входа на карточку с повтором,
  ≈ +$0,3/мес. На модели не проверялось.
- **Докачка страницы — только DeepMind, Hugging Face, Mistral и OpenAI** (`PAGE_FETCH_SOURCES`;
  OpenAI — с 07.10.2026, рашэнне аўтара: анонс в фиде 130–150 знаков, ~4 новости
  из 10 уходили в `failed`; подпись ссылок «(opens in a new window)» вырезается
  в `parse_article`, `LINK_HINT_RE`),
  и только перед генерацией, когда body короче `MIN_BODY_CHARS` (400 знаков):
  у них в фиде заголовок и пустой или однострочный текст. Разбор страницы —
  тот же `collect.parse_article`, что и для Anthropic. Текст берётся из того
  `<article>` или `<main>`, где его больше всего, а в `<main>` — без абзацев
  вложенных `<article>`: у Hugging Face (с ~07.10.2026) на странице до восьми
  `<article>` — карточки других постов, сам пост в `<main>`; разбор «первого
  `<article>`» давал 0 знаков, и посты HF уходили в `failed`
  (`tests/test_parse_article.py`). У Mistral статья —
  в `<article id="blogpost">`, меню и подвал снаружи; шапка статьи (дата,
  автор, «Back to Blog») — короткие абзацы без точки, фильтр их отсекает.
  Проверено 03.10.2026 на четырёх статьях: 2800–4200 знаков текста самой
  статьи; тест — `test_mistral_page_fetch_gives_article_text` на каркасе
  страницы (`tests/fixtures/article_mistral.html`). Поменяют вёрстку —
  материалы Mistral начнут уходить в `failed` с «мала тэксту». Для triage хватает
  заголовка, поэтому страницы отсеянного не качаются вовсе. У остальных RSS
  страницы не качаем (спека, §3, п. 4); если текста меньше `MIN_BODY_ANY`,
  материал уходит в `failed` — пересказывать нечего.
- **Triage** — Haiku 4.5, заголовок и начало текста, ответ по JSON-схеме
  (`prompts.TRIAGE_SCHEMA`). Мусор (реклама TechCrunch, не-ИИ посты Willison)
  отсекается не кодом по источнику, а промптом: у важности 1 явно перечислено,
  что это такое. Промпт слишком мал для кэша Haiku (минимум 4096 токенов).
- **Генерация и fix** — Sonnet 5. System prompt — два блока: первый — стайлгайд,
  глоссарий, антикальки и имена целиком (`prompts.reference_block`, ~22 тыс. токенов),
  с кэшем на 5 минут (`prompts.CACHE_CONTROL`); второй — инструкция задачи. Ничего переменного (даты,
  счётчики) в первый блок не класть — сломает кэш. Общего кэша у генерации и fix
  нет, хотя первый блок у них одинаковый: на прогоне 24.09.2026 fix записал кэш
  заново (20713 токенов против 20666 у генерации) — судя по разнице, JSON-схема
  ответа входит в кэшируемый префикс, а схемы у них разные. Внутри батча кэш
  работает лишь отчасти: запросы идут параллельно, Anthropic обещает попадания
  «по возможности» (30–98%). 24.09.2026 — 1 запись и 19 чтений на 20 запросов,
  07.10.2026 — 2 записи и 2 чтения на 4, по сумме 13-карточного батча — около
  10 записей. Поэтому TTL — 5 минут, а не час (журнал сайта, 07.10.2026,
  «этап 9»): запись 1,25× входа вместо 2×, а запросам одного батча, которые
  стартуют с разницей в секунды, 5 минут хватает. Строка «Забран батч» в логе
  печатает токены записи и чтения кэша — по ней видно долю попаданий;
  `usage_cost` считает запись по TTL из ответа (`cache_creation`).
- **Тон пересказа** (стайлгайд сайта, «Тон пересказа», дополнено 24.09.2026) —
  прямыми словами в `prompts.TONE`, не ссылкой. Меняется правило в стайлгайде —
  меняется и там.
- **Слои карточки без повторов — `prompts.LAYERS`** (замечание автора, журнал
  сайта, 25.09.2026): тезис не повторяет заголовок, summary — тезис, пересказ
  не начинается с тезиса; пример автора «плохо / хорошо» — прямо в промпте,
  наркамаўкай. **Пересказ самодостаточен:** с 03.10.2026 лента сайта
  показывает заголовок и тезис, окно — заголовок, тезис и пересказ,
  summary не видно нигде (`Feed.tsx` сайта; решение автора, журнал сайта,
  «Решения автора после этапа 8е»). Прежнее разрешение пересказу опираться
  на факты summary снято — все важные факты, и те, что в summary, пересказ
  несёт сам. Summary в карточке остаётся (схема, проверки публикации).
  На модели обе правки не проверялись — первая проверка на живых PR.
- **Частые русизмы и русская грамматика — прямым списком в `prompts.LANGUAGE`**,
  дата публикации — запретом в `prompts.DATES` (этап 8, журнал сайта, 25.09.2026).
  Антикальки ловят то же линтером, но уже после генерации, и fix стоит денег;
  дешевле не писать так сразу. Список — самое частое из правок судьи, не весь
  словарь.
- **Имена людей — `ai-news-names.json` сайта:** `write` — как пишет модель
  (наркамаўка), `be` — что будет на сайте после конвертера. Модели показывается
  `write`; при `tarask` ещё и `be` — только там, где конвертер меняет имя
  («Уілісан» → «Ўілісан»): тот же блок видит судья корпуса. Тест `test_names_convert_to_be` сверяет
  `write → be` настоящим конвертером — добавил имя, прогони его.
- **Инструкции модели — на беларускай (наркамаўка), не на русском.** Русская
  инструкция тянула бы модель в русизмы — ровно то, что ловит линтер.
- **Разметка терминов — `{{term:slug|словоформа}}`, а не `{{term:slug}}`** из
  примера в плане: беларуский термин склоняется («пасля файн-цюнінгу»), и одного
  слага мало, чтобы показать слово в нужном падеже. Слаг — `prompts.slug(term)`,
  неизвестный слаг снимается с заметкой в карточке. В заголовке разметки нет.
  Имена людей модель пишет `{{name:…}}` — это только для конвертера, в карточке
  маркер снимается.
- **Конвертер (только `tarask`) — настоящий npm-пакет `taraskevizer`**, версия зафиксирована
  в `tools/taraskevize/package.json`. Python зовёт `node convert.mjs` одним
  процессом на пачку текстов (JSON через stdin/stdout). Правила тарашкевіцы
  сами не переписываем (журнал сайта, 24.09.2026). Путь выбран потому, что
  питоновской реализации нет, а Node на машинах и в Actions есть.
- **Настройки конвертера — как у веб-версии, через которую делался корпус:**
  `g: false`, `j: "never"`, `variations: "no"`. Не `"first"`: он берёт первую
  *альтернативу* слова и массово даёт «у вадным», «дадзеных» → «зьвестак».
  С `"no"` повторная конвертация эталона отличается от него в 5 словах из 3074.
- **Guard-маркеры — синтаксис самого пакета `<.текст>`, ставятся ДО конвертера**
  (`tarask.protect`): латиница целиком, URL, `код`, открывающие части маркеров
  и слова из `ai-news-converter-guards.json` сайта — известные поломки конвертера
  (Шах → Шаг, трэніроўкамі → трэнаваньнемі). До, а не табличной заменой после:
  не нужно знать, во что конвертер превращает каждую форму слова.
- **Предлог «у/ў» сразу после маркера** (`tarask.fix_u_after_markers`). Конвертер
  сам ставит «ў» после гласной, но «}}» маркера закрывает ему предыдущее слово:
  «{{term:…|раунд фінансавання}} у гісторыі» оставалось с «у». После конвертера
  то же правило применяется только на стыке с маркером и только к отдельному
  предлогу, не к началу слова.
- **Незнакомые поломки не проходят молча** (`tarask.suspicious_changes`):
  изменившееся имя в `{{name:…}}` и слово, похожее на себя до конвертера меньше
  чем на `SUSPICIOUS_RATIO`, уходят в `review_notes` карточки. Отсюда пополняется
  guard-словарь.
- **Линтер — по тексту, который пойдёт на сайт** (при `tarask` — после
  конвертера), по `ai-news-anti-calques.json` сайта. Фраза словаря ищется как
  записана и, при `tarask`, ещё и после конвертера — и в склонённых
  формах по закрытому списку окончаний (`lint.ENDINGS`). Не «любое продолжение
  слова»: «лічыцца» ловило бы «лічба». Где этого мало — поле `match` в записи
  словаря (так сделано для «дадзены» против «дадзеныя» и для «мадэлей»).
  Фраза «глагол в инфинитиве + слово» ищется и с разрывом, и в обратном порядке
  («удзел у ім таксама прынялі»), разрыв — только слова, не знаки.
- **Механика — кодом, не моделью.** `lint.normalize` до конвертера исправляет
  латинскую букву-двойник в кириллическом слове («лімiт»), «2$» → «2 $» и
  десятичную точку перед % и валютой («42.92%» → «42,92%»), пару прямых
  кавычек → «ёлачкі» и вырезает HTML-комментарии (`<!-- guard -->` однажды
  доехал до карточки); версии моделей не трогает. Что поменялось — в `review_notes` как «аўтавыпраўленьне».
  Встроенные правила `lint.BUILTIN` помечают для fix буквы и/щ/ъ и оставшуюся
  смесь алфавитов в слове — их кодом не исправить. Замер на корпусе: из 90
  правок судьи эти правила ловят 13 (6 исправляются сразу, 7 уходят на fix).
- **Оборванный текст — назад на генерацию** (`lint.truncated`): thesis, summary
  или retelling, который кончается не концом предложения. Так выглядит прямая
  кавычка перед цитатой: JSON-схема принимает её за конец поля (прогон на
  корпусе 25.09.2026, «працуе як»). Ни конвертер, ни fix это не чинят.
- **Fix получает предложение наркамаўкай**, не тарашкевіцей: пишет модель лучше
  на ней. Дальше про конвертер — только при `tarask`. Предложения до и после конвертера сопоставляются по номеру — конвертер
  пунктуацию не трогает; если разбивка всё же разошлась, предложение не
  правится и это пишется в заметки. Исправленное снова идёт через конвертер,
  остаток попаданий линтера — в `review_notes`.
- **Карточка** — `output/cards/<hash>.json`: поля по формату этапа 5, текст
  в орфографии `AI_NEWS_ORTHOGRAPHY` с разметкой терминов, `review_notes` для ревью и `narkamauka` —
  что сгенерировала модель до конвертера, для разбора ошибок конвертера.
- **Предохранители бюджета** (журнал сайта, 02.10.2026, «Этап 8а»; пересмотрены
  03.10.2026 — «потолок 10 в сутки снят»: лента берёт **все** ИИ-новости,
  прошедшие triage; 07.10.2026 — «два цикла в сутки»: по факту карточка
  стоит $0,05–0,07, ≈ $20–28/мес, лимит консоли $30). Потолки генераций
  — аварийные, а не норма. Все три считаются по таблице `batch` состояния,
  без вызовов API:
  - `MAX_GENERATE_PER_DAY` = 40 генераций за сутки **по Мінску** (UTC+3,
    перевода часов нет) — сумма `requests` батчей `generate`, отправленных
    с полуночи, обоих циклов вместе. Вдвое выше ожидаемых ~20 в сутки: ловит ошибку вроде
    повторной генерации всей очереди, а лишнее в день наплыва новостей
    уходит в следующий суточный батч. Считаются и неудачные: за них тоже
    платим. Triage и fix в этот потолок не входят;
  - `MAX_GENERATE_PER_RUN` = `MAX_GENERATE_PER_DAY`: суточный батч должен
    взять все 40 за раз. Порядок — самые важные первыми, внутри важности —
    самые свежие по дате публикации: в день наплыва «старые первыми» дали
    бы ленту недельной давности; ждущее генерации дольше `MAX_AGE_DAYS`
    уходит в `too_old` (`expire_triaged`).
    При `--wait` — на весь процесс, а не на каждый круг (`run_started`);
  - месячный бюджет `AI_NEWS_MONTHLY_BUDGET_USD` (по умолчанию 28) — сумма
    оценок `usage.usd` батчей, отправленных с начала календарного месяца
    по Мінску, ×`COST_FACTOR`. С 03.10.2026 множитель **1,0** — бюджет
    сверяется с голой оценкой (журнал сайта, 03.10.2026); до того был 1,5:
    оценка занижала счёт консоли в 1,6 раза (журнал сайта, 25.09.2026). Достигнут — новые батчи (triage,
    генерация, fix) не отправляются, готовые забираются, черновики идут
    в публикацию. Выход с кодом 0: строка в лог, аннотация `::warning::`
    и жирная строка в summary прогона. Не красный прогон намеренно — иначе
    письмо о провале 12 раз в сутки до конца месяца.
  Не забранный батч в бюджет ещё не входит: его цена известна только при
  заборе. Перебор ограничен одним запуском — до 40 генераций и triage.
  `--status` (и конец каждого прогона) печатает: сколько отобранного ждёт
  генерации — по дням публикации по Мінску (`waiting_line`), потрачено
  за месяц ×`COST_FACTOR`, остаток бюджета, генераций за сутки; те же
  строки — в summary прогона.
- **Генерация и fix — только по флагам `--generate` и `--fix`** (журнал
  сайта, 03.10.2026, «Этап 8г»; с 07.10.2026 — два цикла, «Этап 9»).
  Каждый батч пишет справочный блок в кэш заново (между прогонами кэш
  не живёт), поэтому батч в каждом прогоне платил бы лишние записи. Поэтому в Actions
  генерация — один прогон за цикл, fix — другой, циклов два в сутки
  (воркфлоу ниже). Без флагов запуск забирает готовые батчи
  и отправляет только triage: он на Haiku без кэша, маленькие батчи ему
  ничего не стоят. `run_once(generate=…, fix=…)` по умолчанию разрешает оба —
  так написаны тесты полного круга. Fix, кроме того, не уходит, если батч
  fix уже отправлялся за последние `FIX_MIN_INTERVAL` (6 часов при цикле
  в 12: прогон в очереди опаздывает) — страховка от повтора того же прогона
  (запасной прогон после упавшего прогона Worker'а, перезапуск руками);
  сверяет `test_fix_at_most_once_a_cycle`.

- **Английский текст карточки — запрос `e-<hash>` в батче генерации**
  (с 08.10.2026; лента `/en/ai-naviny` сайта, `claude/ai-news-en-spec.md` и
  `-plan.md` там). Свой проход по исходной статье, не перевод беларуской
  карточки (решение автора 07.10.2026). В том же батче, что генерация: текст
  статьи живёт в состоянии только до черновика (`forget_body`), отдельного
  прогона нет. Промпт — `prompts.EN_TASK` на английском, без справочного
  блока и кэша, `effort: low`, схема `prompts.EN_SCHEMA`; вход — `en_user`:
  тот же основной и второй источник, что у генерации, плюс компания
  по triage (`pipeline.company`). Беларуский промпт генерации не тронут.
  - **Сломанный английский беларускую карточку не держит.** Не пришёл, ошибка,
    оборван, разметка `{{…}}`, HTML-комментарий или ссылка — черновик уходит
    без полей `en_*`, в `review_notes` — заметка `en` с причиной, в лог —
    строка. Повтора нет: текст статьи к тому времени стёрт. Точку в конце
    заголовка снимает код (`pipeline.english`).
  - **Поля в черновике** — `en_title`, `en_thesis`, `en_retelling` (абзацы
    через пустую строку). Fix и линтер их не трогают — они про беларуский.
    Беларуская генерация ушла на повтор — английский результат выбрасывается
    и пишется заново вместе с ней.
  - **Потолок генераций — про беларуские.** В `batch.requests` пишется число
    материалов, а не запросов (`submit`): иначе английский вдвое срезал бы
    суточный потолок 40. Деньги английского — в общей сумме батча (бюджет),
    отдельно — строкой «из них английский текст: N результатов, ≈ $X» под
    «Забран батч generate» и полем `en_usd` в `batch.usage`.

## Устройство публикации, если правишь код

- **Английские поля на сайте** — `en_title`, `en_thesis`, `en_retelling`
  (массив абзацев) сразу за беларуским текстом, только когда все три есть.
  `check()` проверяет их через `en_fatal` (неполный набор, пустое поле,
  оборванный пересказ, разметка `{{…}}`) и даёт заметки (точка в заголовке,
  тезис без точки, HTML-комментарий). `plan_pr` сломанный английский снимает
  (`without_english`) с заметкой `en` — беларуская карточка идёт в PR.
  Копия на сайте — `publishCheck`/`enFatal` в `src/lib/naviny.ts`, сверяет
  `test_check_same_as_site_dashboard` (английские случаи — в `PARITY_CASES`).
  Заметки английских полей встают к своей строке (`EN_NOTE_RE`), с беларускими
  одноимёнными не склеиваются.
- **Формат карточки на сайте — `site_card`**, а не черновик целиком. Тексты
  наверху файла (диф начинается с того, что читают), пересказ — массив абзацев,
  по строке на абзац, `ensure_ascii=False`. Служебного нет: `status` (файл в
  `main` и есть «опубликовано»), `review_notes`, `lint`, `narkamauka` — в
  черновике остаются, на сайт не едут. `id` — имя файла, внутри не дублируется.
  Решение и причины — журнал сайта, 25.09.2026, этап 5.
- **Коммит через Git Data API**, без локального клона: ветка из базы, одно
  дерево со всеми карточками, один коммит, новая ветка `naviny/<дата-время>`,
  PR. Рабочая копия сайта у автора не трогается. Бот только создаёт ветки
  с префиксом `BRANCH_PREFIX` (POST refs, не PATCH) и никогда не двигает
  существующие — защиты веток у приватного репозитория на бесплатном плане нет.
- **`review_notes` → комментарии к строкам дифа** (`comments_for`), одним
  review с `event: COMMENT`. Строка — по полю из начала `detail`, в пересказе —
  по абзацу с процитированным в «…» (`anchor`); без поля — строка заголовка.
  Одинаковое наблюдение из разных полей склеивается в одно с «×N». Не встали
  комментарии — те же заметки дописываются в описание PR, выход с кодом 1.
- **Что не пускается в PR** (`check`): оборванный пересказ, нечитаемая дата,
  id не sha1 (из него путь файла), пустое поле, источник без http-ссылки.
  Такое правкой слова в дифе не исправить. Остальное — заметкой «публікацыя»:
  тезис без точки, HTML-комментарий, прямые кавычки, неснятый `{{name:…}}`.
  Не вошедшие перечисляются в описании PR.
- **Заметки о содержании — `content_notes`, отдельно от `check()`** (этап 8б,
  журнал сайта, 03.10.2026): правила промпта, которые модель нарушала
  в первом PR. Тоже «публікацыя», карточка в PR идёт:
  - относительная дата в тезисе, summary, пересказе (`REL_DATE_RE`: дни
    недели во всех падежах, «учора», «сёння», «на выхадных», «на мінулым
    тыдні», «два месяцы таму»…) — в заметке найденное слово, по нему она
    встаёт к своему абзацу. «Выхадныя» — только с «на / у / мінулыя…»:
    «выхадных токенаў» — не дата;
  - длина пересказа вне `prompts.RETELLING_WORDS` — то же число, что
    в промпте (константа одна, текст промпта от неё не изменился). Тире
    и знаки словами не считаются;
  - повтор тезиса в первом абзаце пересказа и в summary: доля значимых
    слов тезиса (без стоп-слов, по основе — первые `STEM_LEN` букв;
    латиница и числа целиком), которые есть и там, выше `REPEAT_SHARE`
    и не меньше `REPEAT_MIN_SHARED` общих. Порог подобран на пяти
    карточках первого PR — `tests/fixtures/naviny_pr1`; повтор,
    пересказанный синонимами, так не ловится (`c773f1b` в фикстурах).
    Меняешь порог или стоп-слова — прогони `test_repeat_threshold_on_first_pr`.
  На сайт эти заметки не перенесены и переносить не надо: дашборд правит
  уже опубликованное, а заметки нужны на ревью PR.
- **`check()` и `paragraphs()` повторены в сайте** — `src/lib/naviny.ts`
  (`publishCheck`, `paragraphs`): дашборд сайта проверяет ими правку уже
  опубликованной карточки перед коммитом в ветку деплоя — на проде `main`
  (журнал сайта, 25.09.2026, «правка опубликованных карточек из дашборда»). Меняешь правило или текст
  сообщения — меняй в обоих местах; тест `test_check_same_as_site_dashboard`
  гоняет одни и те же карточки через обе копии и падает на любом расхождении
  (нужен репозиторий сайта рядом и Node 22.6+, иначе тест пропускается).
  `content_notes` в сверку не входит — её в сайте нет намеренно.
- **Второй раз карточка не предлагается**: таблица `publication` в состоянии
  (предложенные и отсеянные) плюс файлы, уже лежащие в `content/naviny` базы
  (`published_ids`, через деревья: Contents API отдаёт не больше 1000 файлов).
  Отклонить карточку = удалить её файл в PR.
- **Автомерж (решение автора, 04.10.2026): PR вливается сразу** —
  `publish.py --merge`, `GitHub.merge`: `PUT /pulls/N/merge`, squash, `sha` — коммит
  ветки (сдвинули ветку — 409, ничего не вольётся). Ручного утверждения нет:
  качество — `check()`, `content_notes`, лингвист и fix внутри процесса.
  Заметки остаются в закрытом PR. Мерж упал — выход с кодом 1, PR открыт,
  карточки уже в `publication` и второй раз не уйдут: влить вручную.
  Выключатель — переменная репозитория `AI_NEWS_AUTOMERGE` = `off` (шаг
  «Публикация» в воркфлоу). Тест — `test_merge_squashes_with_head_sha_and_failure_keeps_state`.
- **Значимые предупреждения — аннотациями Actions** (`collect.actions_warning`,
  04.10.2026): «НЕ ВОШЛА», «комментарии к строкам не встали», «ПРОПУЩЕН
  источник», материал снят после `MAX_ATTEMPTS` попыток (повторы — нет),
  исчерпанный бюджет (`pipeline.announce`). Панель «Стан навін» в админке
  сайта читает их через API — логи без токена не читаются. Новое значимое
  предупреждение — тоже через `actions_warning`, иначе в панели его не будет.
- **Один PR на запуск publish.py**, пустой не открывается. Сам publish.py
  в Actions запускается два раза в сутки, раз за цикл (воркфлоу ниже);
  черновики не удаляет — предложенное отсеивается таблицей `publication`,
  поэтому всё, что накопилось в `output/cards` за цикл, уходит в один PR
  (`test_drafts_of_a_day_go_into_one_pr_and_nothing_is_lost`).

## Устройство запуска, если правишь воркфлоу

`.github/workflows/harvest.yml`, прогон раз в 2 часа по нечётным часам UTC плюс
ручной запуск. Решение и причины — журнал сайта, 25.09.2026, этап 7; запуск
Worker'ом и два цикла — журнал сайта, 07.10.2026, «Этап 9».

- **Кто запускает.** Основной путь — Worker `strymy-bot` в Cloudflare
  (репозиторий `streaminfo-sitebot`, папка `worker/`, его `CLAUDE.md`,
  «Расписание и EventSub»): в минуту 17 нечётных часов он шлёт
  `workflow_dispatch` с входом `kind`. `schedule` GitHub выкидывает прогоны
  (03–04.10.2026 — по 3 в сутки), `workflow_dispatch` ставится в очередь сразу.
  Опоздания у `schedule` здесь небольшие, 10–25 минут; дело в выпавших.
- **Запасной путь — `schedule` в минуту 47**, те же часы. Задача `plan`
  определяет вид прогона и ищет через API прогон Worker'а того же вида
  (`event=workflow_dispatch`, имя `harvest: <kind>` — его задаёт `run-name`)
  за последние 100 минут, успешный или ещё идущий. Нашёлся — задача
  `harvest` пропускается, прогон зелёный и ничего не делает. Прогон Worker'а
  упал — запасной его повторяет. API не ответил — запасной идёт: лишний
  прогон дешевле пропущенного. Замолчит Worker — всё идёт по `schedule`,
  на 30 минут позже.
- **Вид прогона (`kind`):** `collect` — сбор и triage, `generate` — плюс батч
  генерации, `fix` — плюс батч fix, `publish` — плюс PR с карточками. Ручной
  запуск — Run workflow, выпадающий список; без выбора — `collect`. У запасного
  прогона вид — по строке `github.event.schedule` (`case` в шаге «Вид
  прогона»), а не по часам: прогон в очереди опаздывает. Строки cron, `case`
  и таблица часов в `worker/src/harvest.js` бота должны совпадать: здесь
  сверяет `test_workflow_two_cycles_a_day`, там — тест Worker'а.
- **`concurrency: harvest` — у задачи `harvest`, а не у всего воркфлоу**:
  задача `plan` не встаёт в очередь за идущим прогоном и успевает понять,
  что прогон Worker'а идёт.
- **Состояние между прогонами — `actions/cache`, не git.** В кэш уходят
  `data/state.sqlite` и `output/cards` (черновики, ещё не попавшие в PR: упади
  публикация — карточка иначе пропала бы вместе с раннером, а материал уже
  `draft`). Ключ кэша неизменяем, поэтому у каждого прогона свой ключ, а
  восстанавливается самый свежий по префиксу `ai-news-state-`. В git нельзя:
  репозиторий публичный, а в `article` временно лежат тексты чужих статей —
  в истории они остались бы навсегда; плюс двоичный файл каждые 2 часа.
- **Сохранение — отдельным шагом с `always()`**, а не в конце успешной задачи:
  иначе батч, отправленный перед упавшим шагом, был бы оплачен и потерян.
  Не сохраняется, если не прошла проверка состояния: пустой файл затёр бы кэш.
- **Кэша нет, а пайплайн включён — красный прогон**, а не молчаливый старт с
  нуля: пустое состояние заново отправило бы в модель всё за 7 дней. Осознанно
  начать с нуля — ручной запуск с галкой `cold_start`. С выключенным пайплайном
  пустой старт бесплатен и проходит сам.
- **`concurrency: harvest`** — прогоны не пересекаются: два прогона прочитали бы
  одно состояние, и сохранилось бы только последнее.
- **Платная часть выключена переменной.** Пайплайн и публикация идут, только
  если переменная репозитория `AI_NEWS_PIPELINE` = `on` (Settings → Secrets and
  variables → Actions → Variables). Коллектор бесплатный и идёт всегда — кэш
  состояния тёплый к моменту включения.
- **`AI_NEWS_SITE_BRANCH`** (переменная, по умолчанию `naviny-test`) — ветка
  сайта, откуда checkout'ом берутся глоссарий и словари и куда открывается PR.
  В `main` сайта до запуска раздела нет фронта `/naviny` и части словарей.
  Словари правятся в другой ветке — до `naviny-test` они доезжают только мержем.
- **`AI_NEWS_ORTHOGRAPHY`** (переменная, по умолчанию `narkamauka`) — Node
  и `npm ci` конвертера ставятся только при `tarask`.
- **Секреты:** `ANTHROPIC_API_KEY` (в шагах он становится переменной
  `AI_NEWS_ANTHROPIC_KEY`) и `AI_NEWS_SITE_TOKEN`. Дубликат под именем
  `AI_NEWS_ANTHROPIC_KEY` не заводить. Сайт приватный,
  его checkout идёт тем же токеном публикации (Contents: read), deploy key
  не нужен. Шаг «Секреты платной части» называет, какого секрета нет.
- **Один PR за цикл, два в сутки** (журнал сайта, 02.10.2026, «Этап 8а»:
  12 PR в сутки — 12 раз в день открывать GitHub; 07.10.2026 — два цикла).
  Коллектор и пайплайн — каждый прогон, шаг «Публикация» — только в прогоне
  вида `publish`: 05:17 и 17:17 UTC (08:17 и 20:17 по Мінску) или ручной
  запуск. Сверяет `test_workflow_publishes_twice_a_day_or_by_hand`.
  В остальных прогонах шаг «Публикация — не в этом прогоне» пишет в summary,
  сколько черновиков ждёт в кэше.
- **Генерация и fix — по одному батчу за цикл, два цикла в сутки**
  (журнал сайта, 03.10.2026, «Этап 8г»; 07.10.2026, «Этап 9»: новость на
  сайте не позже чем через сутки). Цикл, UTC:
  23:17 / 11:17 — генерация отправлена (`GENERATE`, флаг `--generate`);
  01:17 / 13:17 — генерация забрана, чистые карточки готовы, fix отправлен
  (`FIX`, флаг `--fix`); 03:17 / 15:17 — fix забран; 05:17 / 17:17 —
  публикация. Худший случай для новости — около 20 часов: вышла сразу
  после сбора перед генерацией, ждёт следующую через 12 часов, потом
  6 часов цепочки. Суточный потолок генераций (по Мінску) — на оба цикла
  вместе: 23:17 UTC по Мінску уже следующие сутки (02:17), 11:17 — те же
  (14:17). Triage — в каждом прогоне. Батч не успел к своему прогону —
  забирается следующим, а карточки с правками fix уходят в PR следующего
  цикла; это допустимо, не чинить. Ручной запуск любого вида — Run workflow
  с выбором `kind`. Что карточки цепочки доходят до публикации —
  `test_daily_chain_cards_reach_publication`.
- **Шаги после коллектора — `!cancelled()`**: упавший коллектор не мешает
  забрать уже оплаченные батчи, но прогон всё равно красный. Письмо о красном
  прогоне — штатное GitHub, отдельно не настраивается.

## Чего не делать

- Не подделывай User-Agent браузера или чужого сервиса, чтобы пройти защиту от ботов.
- Не скрейпь страницы источников, у которых есть RSS: body берётся из фида
  (спека, §3, п. 4). Исключения — Anthropic (у него фида нет) и докачка
  `PAGE_FETCH_SOURCES` (DeepMind, Hugging Face, Mistral, OpenAI: в фиде нет текста
  или только короткий анонс).
  Новое исключение — только решением автора.
- Не определяй новое по `lastmod`: он меняется при правке старых статей.
- Не коммить `data/state.sqlite` и `output/cards`: в состоянии тексты чужих статей,
  репозиторий публичный. Между прогонами Actions они живут в кэше.
- Не заводи здесь `claude/` с журналом и спеками — они в репозитории сайта.
- Не читай ключ из `ANTHROPIC_API_KEY` и не полагайся на то, что SDK найдёт его сам.
- Не копируй сюда глоссарий, стайлгайд, корпус и отчёты прогона по корпусу:
  этот репозиторий публичный.
- Не переписывай правила тарашкевіцы в Python и не патчи `node_modules`:
  поломку конвертера — в guard-словарь сайта.
- Не удаляй `tarask.py`, `tools/taraskevize` и guard-словарь сайта, хотя
  по умолчанию они не работают: на их место встанет свой конвертер.
- Не пушь из бота в `main` сайта и не двигай существующие ветки: публикация —
  только через PR (с 04.10.2026 его вливает сам бот, `publish.py --merge`;
  выключатель — `AI_NEWS_AUTOMERGE` = `off`).
- Не клади токен GitHub в код и не печатай его в лог; `.env.local` не коммить.
- Не гоняй генерацию синхронными вызовами по кругу: всё через Batch API, он вдвое
  дешевле и именно он пойдёт в работу.
