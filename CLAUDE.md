# CLAUDE.md — ai-news-harvester

Контекст для Claude Code и любого нового чата, который откроет этот репозиторий.

## Что это

Сборщик новостей об ИИ для будущего раздела `mashninski.com/naviny`. Два шага:

- **коллектор** (`collect.py`, этап 3 плана) — скачивает 8 источников, приводит
  записи к общему виду, отбрасывает уже виденное, склеивает одну новость из
  разных источников;
- **пайплайн** (`pipeline.py`, этап 4) — triage на Haiku 4.5, генерация на
  Sonnet 5, конвертер в тарашкевіцу с guard-маркерами, линтер антикалек,
  fix-проход. Всё через Batch API. На выходе черновики карточек
  `output/cards/<hash>.json`.

Публикации (PR в сайт, этап 5), фронта (этап 6) и запуска по расписанию (этап 7)
тут ещё нет.

Полная спека и план — в **приватном репозитории сайта** `mashninski-site`
(локально `D:\production\mashninski-site`): `claude/ai-news-spec.md` — как устроено
(§2 — источники, §5 — архитектура), `claude/ai-news-plan.md` — этапы и стоимость.
Хронология решений — `claude/journal.md` там же.

Своего журнала у этого репозитория нет и заводить его не надо: продуктовые решения
живут в журнале сайта, здесь — только устройство кода.

## Раскладка

```
collect.py              коллектор
pipeline.py             пайплайн: triage → генерация → конвертер → линтер → fix → черновик
llm.py                  клиент Anthropic (ключ из AI_NEWS_ANTHROPIC_KEY), модели
prompts.py              промпты triage, генерации, fix; сборка system prompt
tarask.py               конвертер: guard-маркеры, вызов Node, поиск подозрительных замен
lint.py                 линтер антикалек, разбивка на предложения
tools/taraskevize/      Node-подпроект: npm-пакет taraskevizer и convert.mjs
schema.sql              схема файла состояния, выполняется при каждом запуске
data/state.sqlite       состояние коллектора и пайплайна. Пока в .gitignore — этап 7
output/cards/           черновики карточек, в .gitignore — дальше их везёт этап 5
eval_corpus.py          прогон на эталонном корпусе сайта (критерий этапа 2)
data/eval/              его входы, карточки и отчёт; в .gitignore
api_check.py            один вызов API — проверка ключа (критерий этапа 0)
probe_feeds.py          ручная проверка фидов-кандидатов перед добавлением
tests/                  pytest; сеть и API не нужны. Тесты конвертера — нужен node
requirements.txt
```

## Запуск

```bash
pip install -r requirements.txt
(cd tools/taraskevize && npm ci)   # конвертер; нужен Node 20+
python collect.py              # печатает новые материалы, записывает их в состояние
python collect.py --dry-run    # то же, но состояние не трогает
python collect.py --json out.json   # плюс новые материалы в JSON
python pipeline.py             # забрать готовые батчи, отправить новые
python pipeline.py --wait      # ходить по кругу, пока все батчи не вернутся
python pipeline.py --status    # что где лежит и сколько потрачено
python -m pytest               # тесты
```

Коллектору ключей не нужно. Пайплайну нужны:

- `AI_NEWS_ANTHROPIC_KEY` — ключ Anthropic API. **Не `ANTHROPIC_API_KEY`:** это
  имя в облачных сессиях Claude Code занято самой платформой, и SDK молча взял
  бы не тот ключ. Ключ передаётся в клиент явно (`llm.make_client`);
- репозиторий сайта рядом — `../mashninski-site` или путь в `AI_NEWS_SITE_REPO`.
  Оттуда читаются стайлгайд, глоссарий, антикальки и guard-словарь. Сюда они не
  копируются: сайт приватный, этот репозиторий публичный.

## Устройство, если правишь код

- **Все источники в списке `SOURCES`.** Тип `rss` — через feedparser (Atom он тоже
  читает), тип `sitemap` — свой адаптер. Новый источник — одна строка.
- **Каждый источник в своём try/except** (`collect()`): сеть, таймаут, HTTP-ошибка,
  битый XML роняют только его, в лог идёт `ПРОПУЩЕН источник …`, в отчёте — строка
  «Источники с ошибкой». Покрыто тестом `test_broken_sources_are_skipped_not_fatal`.
- **feedparser не считает ошибкой HTML-страницу и пустой ответ** — отдаёт ноль записей
  без флага ошибки. Поэтому ответ без распознанной версии фида и без записей считается
  ошибкой источника, иначе умерший фид молчал бы. Обрезанный XML, из которого
  feedparser спас часть записей, берётся с предупреждением.
- **Идентичность записи — нормализованный URL** (`url_key`): без `utm_*`, `ref`,
  `fbclid` и подобных меток, без `#якоря`, схемы, `www.` и завершающего слэша,
  параметры отсортированы. `hash` — sha1 от него. В поле `url` лежит `clean_url` —
  рабочая ссылка без меток, по `url_key` ходить нельзя. Новая метка в ссылках
  источника — добавить в `TRACKING_PARAMS`, иначе виденное начнёт возвращаться.
- **Окно свежести `MAX_AGE_DAYS`.** Фиды OpenAI и Hugging Face отдают весь архив
  (сотни записей). Всё старше окна пишется в состояние со статусом `stale`
  и дальше не идёт. Без этого первый прогон выдал бы ~2500 «новых».
- **Anthropic — по sitemap.** Новое — это URL `/news/<slug>`, которого нет в
  состоянии; `lastmod` меняется и при правке старой статьи, поэтому новизну не
  определяет. `lastmod` служит только дешёвым фильтром: страницу с `lastmod`
  старше окна не качаем. Страница качается один раз, только для нового URL;
  не скачалась — URL не пишется в состояние и будет в следующем прогоне.
  Не больше `PAGE_FETCH_LIMIT` страниц за прогон.
- **Дата у Anthropic** — `article:published_time`, если есть; иначе дата текстом
  «Sep 23, 2026» со страницы (в разметке Anthropic есть только она); иначе `lastmod`.
- **Склейка заголовков** (`cluster`, `same_story`): разные источники, публикации
  не дальше `CLUSTER_WINDOW_HOURS`, не меньше `CLUSTER_MIN_SHARED` общих значимых
  слов и не меньше `CLUSTER_MIN_OVERLAP` от более короткого заголовка. Значимые —
  без стоп-слов (`STOPWORDS`: служебные английские и общие для новостей об ИИ
  вроде «launches», «model») и **без слов серии**: слово, которое у источника стоит
  в двух заголовках за окно, — название линейки («gemini», «3.8»), а не признак
  новости. Порог подобран на живых данных, разбор — в журнале сайта, 24.09.2026.
  Меняешь — прогони тесты склейки: там живые пары из этой выборки.
- **Склейка идёт и с прошлыми прогонами.** Пост вендора и статья портала о нём
  обычно приходят в разные прогоны. Новое сравнивается с отданным за окно
  (`load_known`); совпавшее пишется в состояние как `duplicate` с `primary_hash`
  основного и печатается отдельным списком «повторы отданных раньше».
- **Основной в кластере** — уже отданный, иначе пост вендора (`VENDORS`), иначе
  более ранний. Сравнение только с основным, не со всеми участниками кластера —
  иначе цепочка A≈B≈C склеила бы разные A и C.
- **Под браузер не маскируемся.** `USER_AGENT` честный. VentureBeat режет ботов
  (429 всем, кроме браузеров и известных читалок вроде Feedly) — сейчас он штатно
  пропускается каждый прогон. Что с ним делать — решение автора, см. журнал сайта.
- **Текст статей в состоянии — только временно**: body нового материала ждёт
  в таблице `article`, пока пайплайн не сделает карточку или не отсеет материал,
  потом стирается. Постоянно хранится только нужное для дедупа.

## Устройство пайплайна, если правишь код

- **Батчи переживают перезапуск.** Каждый запуск `pipeline.py` сначала забирает
  готовые батчи из таблицы `batch` (отправленные прошлыми запусками), потом
  отправляет новые на всё, что ждёт своего шага в таблице `item`. Шаги:
  `new → triage_sent → triaged → generate_sent → linted → fix_sent → draft`,
  плюс `rejected`, `too_old`, `failed`. Неудачный результат возвращает материал
  на шаг назад, после `MAX_ATTEMPTS` — `failed` с причиной в `error`. Уже
  разобранный результат повторно не разбирается: берутся только материалы, которые
  всё ещё ждут именно этот батч. Схема — `schema.sql`, раздел «Пайплайн».
- **Текст статьи лежит в таблице `article`** — коллектор кладёт туда body новых
  основных материалов (первые 700 слов). Когда карточка готова или материал
  отсеян, текст стирается: в состоянии остаётся только нужное для дедупа.
- **Докачка страницы — только DeepMind и Hugging Face** (`PAGE_FETCH_SOURCES`),
  и только перед генерацией, когда body короче `MIN_BODY_CHARS` (400 знаков):
  у них в фиде заголовок и пустой или однострочный текст. Разбор страницы —
  тот же `collect.parse_article`, что и для Anthropic. Для triage хватает
  заголовка, поэтому страницы отсеянного не качаются вовсе. У остальных RSS
  страницы не качаем (спека, §3, п. 4); если текста меньше `MIN_BODY_ANY`,
  материал уходит в `failed` — пересказывать нечего.
- **Triage** — Haiku 4.5, заголовок и начало текста, ответ по JSON-схеме
  (`prompts.TRIAGE_SCHEMA`). Мусор (реклама TechCrunch, не-ИИ посты Willison)
  отсекается не кодом по источнику, а промптом: у важности 1 явно перечислено,
  что это такое. Промпт слишком мал для кэша Haiku (минимум 4096 токенов).
- **Генерация и fix** — Sonnet 5. System prompt — два блока: первый — стайлгайд,
  глоссарий и антикальки целиком (`prompts.reference_block`, ~22 тыс. токенов),
  с кэшем на 1 час; второй — инструкция задачи. Ничего переменного (даты,
  счётчики) в первый блок не класть — сломает кэш. Общего кэша у генерации и fix
  нет, хотя первый блок у них одинаковый: на прогоне 24.09.2026 fix записал кэш
  заново (20713 токенов против 20666 у генерации) — судя по разнице, JSON-схема
  ответа входит в кэшируемый префикс, а схемы у них разные. Внутри батча кэш
  работает: в генерации 1 запись и 19 чтений на 20 запросов.
- **Тон пересказа** (стайлгайд сайта, «Тон пересказа», дополнено 24.09.2026) —
  прямыми словами в `prompts.TONE`, не ссылкой. Меняется правило в стайлгайде —
  меняется и там.
- **Инструкции модели — на беларускай (наркамаўка), не на русском.** Русская
  инструкция тянула бы модель в русизмы — ровно то, что ловит линтер.
- **Разметка терминов — `{{term:slug|словоформа}}`, а не `{{term:slug}}`** из
  примера в плане: беларуский термин склоняется («пасля файн-цюнінгу»), и одного
  слага мало, чтобы показать слово в нужном падеже. Слаг — `prompts.slug(term)`,
  неизвестный слаг снимается с заметкой в карточке. В заголовке разметки нет.
  Имена людей модель пишет `{{name:…}}` — это только для конвертера, в карточке
  маркер снимается.
- **Конвертер — настоящий npm-пакет `taraskevizer`**, версия зафиксирована
  в `tools/taraskevize/package.json`. Python зовёт `node convert.mjs` одним
  процессом на пачку текстов (JSON через stdin/stdout). Правила тарашкевіцы
  сами не переписываем (журнал сайта, 24.09.2026). Путь выбран потому, что
  питоновской реализации нет, а Node на машинах и в Actions есть.
- **Настройки конвертера — как у веб-версии, через которую делался корпус:**
  `g: false`, `j: "never"`, `variations: "no"`. Не `"first"`: он берёт первую
  *альтернативу* слова и массово даёт «у вадным», «дадзеных» → «зьвестак».
  С `"no"` повторная конвертация эталона отличается от него в 5 словах из 3074.
- **Guard-маркеры — синтаксис самого пакета `<.текст>`, ставятся ДО конвертера**
  (`tarask.protect`): латиница целиком, URL, `код`, открывающие части маркеров
  и слова из `ai-news-converter-guards.json` сайта — известные поломки конвертера
  (Шах → Шаг, трэніроўкамі → трэнаваньнемі). До, а не табличной заменой после:
  не нужно знать, во что конвертер превращает каждую форму слова.
- **Незнакомые поломки не проходят молча** (`tarask.suspicious_changes`):
  изменившееся имя в `{{name:…}}` и слово, похожее на себя до конвертера меньше
  чем на `SUSPICIOUS_RATIO`, уходят в `review_notes` карточки. Отсюда пополняется
  guard-словарь.
- **Линтер — после конвертера**, по `ai-news-anti-calques.json` сайта. Фраза
  словаря ищется в двух видах — как записана и после конвертера — и в склонённых
  формах по закрытому списку окончаний (`lint.ENDINGS`). Не «любое продолжение
  слова»: «лічыцца» ловило бы «лічба». Где этого мало — поле `match` в записи
  словаря (так сделано для «дадзены» против «дадзеныя»).
- **Fix получает предложение наркамаўкай**, не тарашкевіцей: пишет модель лучше
  на ней. Предложения до и после конвертера сопоставляются по номеру — конвертер
  пунктуацию не трогает; если разбивка всё же разошлась, предложение не
  правится и это пишется в заметки. Исправленное снова идёт через конвертер,
  остаток попаданий линтера — в `review_notes`.
- **Карточка** — `output/cards/<hash>.json`: поля по формату этапа 5, текст
  в тарашкевіцы с разметкой терминов, `review_notes` для ревью и `narkamauka` —
  что сгенерировала модель до конвертера, для разбора ошибок конвертера.
- **Потолок `MAX_GENERATE_PER_RUN` генераций за запуск** — страховка от случайной
  траты, самые важные идут первыми. Оценка потраченного — в таблице `batch`,
  `--status` печатает сумму.

## Чего не делать

- Не подделывай User-Agent браузера или чужого сервиса, чтобы пройти защиту от ботов.
- Не скрейпь страницы источников, у которых есть RSS: body берётся из фида
  (спека, §3, п. 4). Единственное исключение — Anthropic, у него фида нет.
- Не определяй новое по `lastmod`: он меняется при правке старых статей.
- Не коммить `data/state.sqlite`, пока этап 7 не решил иначе.
- Не заводи здесь `claude/` с журналом и спеками — они в репозитории сайта.
- Не читай ключ из `ANTHROPIC_API_KEY` и не полагайся на то, что SDK найдёт его сам.
- Не копируй сюда глоссарий, стайлгайд, корпус и отчёты прогона по корпусу:
  этот репозиторий публичный.
- Не переписывай правила тарашкевіцы в Python и не патчи `node_modules`:
  поломку конвертера — в guard-словарь сайта.
- Не гоняй генерацию синхронными вызовами по кругу: всё через Batch API, он вдвое
  дешевле и именно он пойдёт в работу.
